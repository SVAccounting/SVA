# ProOblik — оновлення інтерфейсу проводок (22.11.2026)

## Що змінилося

- У розділі «Сервіс суперадміна → Діючі проводки за операціями» замість одного спільного тексту для всіх проводок тепер відображається суть *кожної* кореспонденції. Зокрема, банківські надходження на рахунок 311 розрізняються за рахунком кредиту (361, 301, 60, 50, 681, 40, 685).
- Прибрано технічні позначки `doc:bin` та інші `doc:*`, зайві статусні плашки та загальні інструкції з екранів перегляду й конструктора проводок. Технічні ключі **залишилися в програмному коді** й у правилах Neon, щоб не порушити сумісність з документами.
- «Змінити» відкриває конструктор та модальне вікно «Редагування проводки». Можна змінити рахунки дебету/кредиту та поле **«Суть операції»**. У вікні для вже відомої кореспонденції вихідні рахунки захищені від випадкового редагування.
- Після редагування користувач зберігає чернетку правила, перевіряє й активує її. Опублікований зміст відображається в списках і підставляється до *нових* проводок документів, створених після початку дії правила. Уже проведені господарські операції та їхні описи не переписуються.
- За відсутності змін опису використовується зміст, заданий в `public/posting-catalog.js` для цієї кореспонденції. Якщо опис у вікні не відрізняється від початкового і рахунки не змінено, зайве правило не створюється.
- Додано перевірку опису на сервері (непорожній текст, не довший за 500 символів); дані зберігаються у JSONB `accounting_rule_versions.config.mappings[].description` (Neon).

## Файли

- `public/posting-catalog.js` — описи вбудованих кореспонденцій.
- `public/rulebook.js` — інтерфейс та модальне редагування.
- `public/theme.css` — адаптивні стилі вікна й таблиці.
- `netlify/functions/rule-engine.js` — перевірка та перенесення описів у правила.
- `netlify/functions/api.js` — застосування індивідуального опису до нових проведень документів.
- `public/index.html`, `public/sw.js` — версії статичних файлів і кешу.

## Встановлення

Замінити файли з архіву у GitHub і задеплоїти Netlify. **Додатковий SQL для цього оновлення не потрібен**, якщо попередня міграція конструктора правил уже встановлена. Існуючі правила без поля `description` продовжують працювати. Робочу базу Neon не було змінено.

## Уточнення

`doc:bin` означає internal source key `document: bank incoming` — «банківська виписка: надходження». Його приховано лише в інтерфейсі, але не перейменовано в бекенді.

Проводка Дт 311 Кт 40 можлива лише за належного обґрунтування конкретної операції. Для стандартного внеску до вже зареєстрованого статутного капіталу зазвичай використовується Дт 311 Кт 46. Каталог показує можливі варіанти, а не гарантує застосовність кожного з них в усіх випадках.

## Перевірка

`npm run test:all` — пройдено. Графічний перегляд в Chromium у робочому середовищі не завершився через зависання браузера; верстка потребує ручного огляду після деплою (десктоп і смартфон).
