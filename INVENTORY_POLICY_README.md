# ProOblik — номенклатура, складський облік і ціноутворення (21.11.2026)

## Порядок встановлення

1. Створити резервну копію робочої бази Neon та перевірити можливість її відновлення.
2. Виконати **inventory_policy_migration.sql** у Neon SQL Editor один раз. Міграція додає довідники, таблицю історії цін, індекси та поле партії, не змінюючи наявні бухгалтерські проведення.
3. Розгорнути файли додатка на GitHub/Netlify. При заміні файлів зберегти вже наявні шрифтові ресурси в `public/fonts` із поточного репозиторію; вони потрібні іншим модулям експорту.
4. Увійти в розділ «Довідники → Види номенклатури», «Одиниці виміру» та звірити типові рахунки за обліковою політикою.
5. Для існуючих товарів вибрати вид і базову одиницю виміру. Якщо позиція має старі складські рухи, необхідно окремо підтвердити **первинну класифікацію**. Історичні проводки не переписуються: після цього провести бухгалтерську звірку залишків.
6. У «Облікова політика» вибрати метод і базу оцінки. Після першого руху запасів метод і рівень оцінки блокуються, щоб не змінити заднім числом собівартість.
7. Для реалізації встановити ціни в розділі «Ціноутворення → Встановлення цін», обравши тип ціни та дату набуття чинності.
8. Перед роботою на реальних даних перевірити в тестовому підприємстві надходження, продаж, переміщення, сторно, FIFO та відповідність ОСВ.

## Розділи й поля

- **Облікова політика:** FIFO, середньозважена (на дату вибуття), ідентифікована собівартість; для FIFO та середньозваженої — облік собівартості по складах або спільний пул підприємства.
- **Види номенклатури:** товари (281/902/702), готова продукція (26/901/701), матеріали (201/943/712), МШП (22/943/712), тара, послуги та роботи (без складського руху, рахунок доходу 703), простий набір як готовий товар (без виробничої комплектації).
- **Одиниці виміру:** окремий довідник із кодами, базова одиниця в картці товару.
- **Ціноутворення:** довідник видів цін і датована історія продажних цін за номенклатурою. Фактична закупівельна собівартість — у документі надходження, не в картці номенклатури.
- **Документи:** прибуткова накладна, видаткова накладна, переміщення, списання; випуск власної готової продукції — Дт 26 Кт 23.
- **Вибір партії:** обов'язковий для методу ідентифікованої собівартості. Для старих списань без партій програма блокує автоматичну ідентифікацію до звірки залишків.

## Обмеження і важливі зауваження

1. Середньозважена собівартість тут обчислюється **на дату операції (рухома середня)**. Періодичну середню за місяць, ретроспективну переоцінку, а також перерахунок після вставки заднім числом не реалізовано.
2. **FIFO по підприємству** — спільна вартісна черга, але фізична кількість перевіряється на конкретному складі. Вибір цього рівня потрібно погодити з обліковою політикою щодо однорідних запасів; не варто вважати дві бази FIFO довільною зміною методу.
3. Початкові кількісні залишки (документ «Початкові залишки ТМЦ») **не формують проводок** — дебет рахунків запасів і кредит початкових сальдо слід звіряти окремо, щоб не подвоїти їх. Для повної процедури запуску обліку потрібне додаткове доопрацювання.
4. «Набір» — це окрема складська позиція, а не калькуляція або автоматичне збирання комплекту з компонентів. Конвертація одиниць виміру та багато штрихкодів для однієї позиції ще не реалізовані.
5. Готова продукція оприбутковується за сумою собівартості, **введеною користувачем** у документі випуску. Автоматична виробнича калькуляція, розподіл 91 і закриття 23 не реалізовані.
6. Придбання ТМЦ із ПДВ та реалізацію слід перевірити за особливостями договорів і облікової політики. Програма не замінює бухгалтерську перевірку.
7. **Ні тестове розгортання Netlify з реальним Neon, ні візуальний мобільний браузерний тест не виконано**; запуски Node-синтаксису та модульні тести покривають лише вибрані контрольні сценарії. Не замінюйте робочу версію без резервної копії та тестової перевірки.
