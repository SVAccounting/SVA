# ProOblik v5 — план рахунків і типові операції (листопад 2026)

База: `ProOblik_inventory_v4_constructor.zip` (збережено розширений складський облік, ролі, зарплату, коригування, звіти та конструктор бухгалтерських правил).

## Що змінено

1. `data/accounts.txt` — **356** рахунків і субрахунків із завантаженого `accounts (2).txt`: `code|name|kind|analytic_enabled|analytic_dimensions|quantity_enabled|quantity_policy`. Значення `-` = невизначено джерелом, не тотожне `0`.
2. `public/app2.js` та `netlify/functions/api.js` — показ і редагування назви, типу, аналітики й кількісних ознак рахунків. Значення зберігаються в `public.accounts`; самі поля *не створюють автоматично* аналітичні або кількісні регістри.
3. `data/typical_operations_2026.json` — **472** записи із завантаженого каталогу, включно з посиланнями на сторінки Інструкції №291 та зауваженнями. В `public/templates.js` міститься резервний набір **468 активних** позицій.
4. **438 балансових кореспонденцій із різними Дт/Кт**, **4 аналітичні перенесення з однаковим рахунком Дт/Кт**, **30 позабалансових записів із одним рахунком**. Із 438 балансових 2 дублікати, 2 позначені як такі, що потребують окремого обґрунтування. Вони імпортуються як **неактивні**, без втрати вихідної інформації.
5. `data/correspondences_291.json` — **951** унікальна кореспонденція синтетичних рахунків із Інструкції №291. Довідковий перегляд: «Сервіс суперадміна → Кореспонденції №291».
6. `public/typical-ops.js` — редактор у Neon з пошуком, архівними шаблонами, типом запису, зауваженнями, включенням/виключенням, журналом змін, можливістю редагування. Усі старі шаблони при *першому* імпорті не видаляються, а стають неактивними.
7. `offbalance_entries` — окремий журнал для позабалансових операцій. Немає вигаданого кредиту/дебету: прихід або списання окремо; контролюється доступ і від'ємний залишок. Такі записи не впливають на баланс або ОСВ.
8. Аналітичні рухи складу (зокрема `281/281`) **не перетворюються на фіктивні проводки**. Для них застосовується складський документ переміщення між складами. Типові операції, що зачіпають запаси, залишаються у довіднику, але пряме проведення з шаблону вимкнене, щоб не створювати проводки без складського руху / руху партій.
9. Видалено старий вбудований набір шаблонів у `public/templates.js`, в якому, зокрема, використовувався `286` для транспортно-заготівельних витрат. У новому плані **286 — необоротні активи й групи вибуття, утримувані для продажу**. У старому коді послуг використання `231` замінено на чинний у новому плані `23`.
10. В модулі зарплати збережено встановлену ставку військового збору **5%** (за податковими нормативами підприємства); у новому каталозі сума проводки вводиться *уже обчисленою*. Автоматичного множення 0,05 на введену суму зарплати в одно-рядковому каталозі немає. Обчислення зарплати/ЄСВ виконує окремий модуль.

## Встановлення на існуючу Neon

**Спочатку створіть Neon branch/backup; не застосовуйте напряму без резервної копії.** При міграції рахунків може змінитися класифікація раніше створених рахунків, тому перевірте залишки, відкриті документи й власні налаштування.

1. У **Neon SQL Editor** виконайте `update_accounts_neon_analytics_2026.sql` — оновлення рахунків та колонок обліку. Збережені бухгалтерські записи залишаються на своїх рахунках; зайві нерозрахункові рахунки можуть прибиратися лише за умовами вихідного SQL.
2. У **Neon SQL Editor** виконайте `typical_catalog_2026_migration.sql` — додає метадані шаблонів, архівує старий каталог на першому запуску, вносить 472 записи і 951 пару, створює позабалансовий журнал. Міграція повторювана: редагування суперадміна не перезаписуються повторним імпортом.
3. Завантажте в GitHub файли **всього** архіву і розгорніть їх у Netlify (той самий проєкт / DATABASE_URL). Не змішуйте `index.html`, `templates.js`, `typical-ops.js` та API з попередніми версіями. У комплекті не дублюються файли шрифтів — **залиште наявну папку `public/fonts` із попередньої версії репозиторію**, її використовує PDF-експорт.
4. Перевірте в ProOblik: «План рахунків», «Типові операції», «Сервіс суперадміна → Редактор типових операцій», «Кореспонденції № 291», «Позабалансовий журнал».
5. У Neon виконайте запити з `VERIFY_CATALOG_2026.sql`, перевірте **472 / 468 активних / 951**, наявність 356 рахунків (без технічного `000` і можливих історичних рахунків). Перевірте в тестовому підприємстві придбання, складський рух, зарплату, ПДВ, позабалансовий запис, ОСВ.

**Не запускати лише старий** `typical_operations_migration.sql` як повну міграцію: він створює базову таблицю без нових колонок і даних. Його можна залишити для історії; повний імпорт — у файлі `typical_catalog_2026_migration.sql`.

## Межі перевірки

- Перевірено структуру файлів, відповідність кодів 356 рахункам, відсутність сторонніх Дт/Кт, дублікати, тип запису, синтаксис JS і всі наявні локальні автоматичні тести.
- **Міграції на реальній Neon не виконувалися**, підключення до вашого середовища й розгортання Netlify не здійснювалися. Не було інтеграційного тесту на копії вашої фактичної БД.
- 951 пари з Інструкції — кореспонденції **синтетичних** рахунків, не автоматичне підтвердження кожної господарської операції.
- Складська аналітика та кількісний облік НЕ створюються одним тільки прапорцем рахунку. Реєстр складських рухів зберігається у власній складській підсистемі ProOblik.
- Нормативність двох спірних пар (`374/631`, `285/902`) додатково не встановлювалася, тому шаблони лишаються вимкненими.
- Вхідний план рахунків містить кілька описових скорочень і неповних назв, напр. рахунок 63. Назви збережено відповідно до наданого текстового файла; за потреби виправте через суперадмінський редактор після звіряння з офіційним джерелом.
