# ProOblik v8.1 — План рахунків: перегляд та редагування

Це оновлення інтерфейсу **на базі `ProOblik_v8_local_posting_editor(1).zip`**. Дані бухгалтерських проведень, журналів, типових операцій і правила v8 не змінювалися.

## Що змінено

1. **Таблиця плану рахунків** тепер знаходиться в окремому контейнері з горизонтальною та вертикальною прокруткою і закріпленою шапкою. Повний набір колонок доступний без прокручування всього сайту до самого низу. При вузькій ширині вона лишається таблицею, а не розпадається на картки.
2. **Форма «Додати новий рахунок»** згорнута при відкритті сторінки. Вона призначена тільки для створення нового рахунку; загальні властивості існуючого змінюються в його картці.
3. **Пошук** за кодом, назвою, типом, ознаками аналітичного/кількісного обліку, розрізами та назвами субконто. Є очищення пошуку та підрахунок результатів.
4. **Клікабельний рядок рахунку:** натисніть на нього або кнопку «Відкрити» (можна також Enter/пробіл після фокуса з клавіатури). Відкривається модальне вікно з кодом, назвою, типом, аналітикою, кількісним обліком і правилами, а також трьома субконто поточного підприємства.
5. **Збереження:** сервер зберігає загальні реквізити через існуючий `/api/accounts` (лише суперадмін), а локальні субконто — через `/api/account-subconto` (суперадмін / адміністратор підприємства). Якщо змінено тільки субконто, загальні реквізити не перезаписуються.
6. Для глобальних змін є додаткове підтвердження. Код чинного рахунку **не редагується**, оскільки використовується у проведеннях і в інших таблицях.
7. При створенні перевіряється дублювання коду; новий рахунок відкривається у своїй картці.

## Що не змінилося

- Призначення загальних рахунків для всіх підприємств;
- Індивідуальні налаштування субконто кожного підприємства;
- Дані історичних проводок (не перераховуються);
- Структура БД Neon та її міграції;
- Попередній механізм версійних бухгалтерських правил.

## Установлення

1. Зробіть резервну копію GitHub або збережіть старий архів.
2. Замініть файли в GitHub файлами з цього ZIP (збережіть налаштування Netlify та Neon).
3. Дочекайтеся деплою та перезавантажте застосунок. У `index.html` оновлені параметри версій CSS/JS, а в `sw.js` змінено ключ кешу.
4. Відкрийте «План рахунків», перевірте скрол, пошук і відкриття картки на рахунку 281, потім збережіть тестову зміну субконто для поточного підприємства.

**Окремий SQL не потрібен**, якщо вже встановлені необхідні міграції v7 та v8. Якщо бачите `relation "account_subconto_settings" does not exist`, спочатку потрібно завершити міграцію v7.

## Перевірки

- `node --check public/app2.js` — без помилок.
- `node --test tests/accounts_ui_v8_1.test.mjs` — чотири тести (таблиця, картка, локальне збереження, пошук).
- Наявні тести для складу, правил, журналів, v8 — пройшли.
- Повну візуальну перевірку Chromium завершити не вдалося (браузер завис у середовищі тестування); рекомендовано перевірити вигляд після деплою.
