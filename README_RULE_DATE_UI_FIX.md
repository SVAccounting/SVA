# ProOblik — відображення майбутніх версій бухгалтерських правил

## Причина відмінності Дт 311 / Кт 40 та Дт 311 / Кт 401

Конструктор зберігає нове правило в `accounting_rule_versions` зі статусом `active` та датою `effective_from`. На сервері активація дозволена **з наступного календарного дня**, тому `active` ще не означає «чинний сьогодні».

- У таблиці чинної кореспонденції відображається правило, що діє сьогодні (`effective_from <= сьогодні`).
- У модальному вікні відкривається остання активована версія, включно з майбутньою.

## Що змінено

- У таблицях «Конструктор бухгалтерської логіки» та «Діючі проводки за операціями» залишено чинні сьогодні Дт/Кт, але **під змістом проводки** тепер показується майбутня зміна, наприклад `З 2026-11-23: Дт 311 · Кт 401`.
- Майбутня активована версія позначена «Запланована версія №… · з …», а не просто «Версія». Заголовок переліку змін теж указує дату початку дії.
- У `index.html` змінено версії ресурсів JS/CSS, аби браузер завантажив нові файли.
- Збережено серверну логіку дат, контроль складських рахунків та незмінність раніше проведених документів.

## Установлення

1. Завантажити всі файли архіву до GitHub замість попередніх (зберігаючи відсутні локальні файли, якщо такі є).
2. Дочекатися завершення деплою Netlify й перезавантажити сторінку.
3. У конструкторі відкрити «Банківська виписка: надходження»: сьогодні буде показано Дт 311 — Кт 40 та майбутню зміну до Дт 311 — Кт 401.
4. Із дати набуття чинності сама основна кореспонденція відображатиметься як Дт 311 — Кт 401.

Новий SQL **не потрібен**. Наявну базу Neon змінювати не потрібно.
