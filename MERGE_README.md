# ProOblik: розширений склад + конструктор суперадміна (21.11.2026)

## Джерела
- `ProOblik_inventory_accounting_prices_v2.zip` — база; склад, `stock_moves.lot_key`, `inventory_revision`, типи номенклатури, ціни й одиниці
- `ProOblik_superadmin_accounting_rulebook.zip` — лише правила, редактор, діагностика, версії, міграція

## Пріоритет сумісності
Основний `netlify/functions/api.js`, `app2.js`, `app3.js`, `app8.js`, схема складу, SQL-міграція складського обліку й тести інвентаризації **збережені зі складської версії**. Інтегровано тільки маршрути правил і точки їх застосування.

## Розгортання
1. Клон/резервна копія Neon; перевірити, що раніше виконано `inventory_policy_migration.sql`.
2. Виконати `accounting_rulebook_migration.sql` у Neon SQL Editor. Це додає версії правил та два необов’язкові поля; старі документи і проводки не змінюються.
3. Перенести файли архіву в GitHub, зберегти папку `public/fonts`, якщо вже існує у репозиторії.
4. Виконати тестове розгортання Netlify. Увійти під суперадміном і створити тестове правило у «Сервіс суперадміна».
5. Перш ніж використовувати для реального обліку, протестувати на тестовій базі надходження двох партій, реалізацію, переміщення, випуск продукції, зарплату, закриття періоду, звітність та зміну правил.

## Безпека й межі конструктора
- Суперадмін визначається сервером за актуальною роллю `users.role`.
- Строк дії нового правила починається не раніше наступного календарного дня. Опублікована версія незмінна.
- У проводках дозволені тільки заміни Дт/Кт без зміни сум. Для складських документів зміна рахунка запасів класу 2 у парі заборонена (інший рахунок у проводці може змінюватися) через ризик розбіжностей зі складською собівартістю. Зміни типу товару і рахунків потрібно узгоджувати зі складом.
- Правила **не** перебудовують уже проведені документи та складські рухи.
- Формули звітів змінюють показники у формах, але **не** виправляють облікові записи.
- Реальне тестування з Neon не проводилося.
